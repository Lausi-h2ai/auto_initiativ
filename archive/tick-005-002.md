# AM-005-002: Onboarding Review Workflow

Status: `done`
Date: 2026-05-15

## Objective

Implement deterministic review and promotion for candidate `user_profile.json`, `master_cv_profile.json`, and `policy.json` snapshots.

## Roles Used

- Coordinator: main session
- Reviewer: pending tick review

## Changes

- Added `backend/app/onboarding/promotion.py`.
- Added onboarding promotion API models in `backend/app/schemas/api.py`.
- Added `GET /onboarding/runs/{run_id}/snapshots`.
- Added `POST /onboarding/runs/{run_id}/promote`.
- Changed import normalization so user profile, master CV, and policy snapshots start as `candidate`.
- Changed evaluate-only gate behavior so linked onboarding snapshots must be `approved` before automated gate use.
- Cleared generated evaluate-only gate results on same-run re-import so stale pass results cannot attach to fresh candidate snapshots.
- Changed malformed stored send-intent JSON handling so evaluate-only returns a blocked gate result with completed audit instead of crashing.
- Added onboarding promotion workflow tests in `backend/tests/test_onboarding_promotion.py`.
- Updated existing import and gate tests for the candidate-to-approved lifecycle.
- Updated `BACKLOG.md`, `CHARTER.md`, and `docs/AGENT_BRIEF.md` so the next recommended tick is `AM-005-003: Onboarding Review Schemas`.

## Result

Onboarding snapshots are no longer treated as approved truth immediately after import. A backend promotion action requires explicit reviewer confirmation for the user profile, master CV, and policy. Promotion validates review-needed provenance, duplicate approved claim IDs, conservative policy defaults, and policy exclusion provenance before marking snapshots `approved`.

The gate now blocks send intents that reference candidate or otherwise unapproved onboarding snapshots.

No Gmail integration, email adapter, send behavior, reservation mode, OpenAI dependency, or autonomous irreversible action was added.
