# AM-002-004: Add Database Dedupe Constraints

Status: `done`
Date: 2026-05-14

## Objective

Add deterministic normalization helpers and database-enforced dedupe constraints without adding gate execution, send APIs, email adapters, Gmail access, or LLM runtime dependencies.

## Decision

Dedupe is enforced on outreach state, not candidate records:

- `send_reservations` owns active in-flight reservation uniqueness.
- `outreach_records` owns completed contacted-recipient and contacted-company uniqueness.
- Policy-derived `dedupe_recipient` and `dedupe_company` flags decide whether company/recipient uniqueness applies for those rows.

## Changes

- Added deterministic recipient email, company domain, company name, and company policy key normalization helpers.
- Added `dedupe_recipient` and `dedupe_company` columns to reservation and outreach models.
- Added partial unique indexes for active reservation recipient/company dedupe.
- Added partial unique indexes for contacted outreach recipient/company dedupe.
- Added Alembic migration `20260514_0002_dedupe_constraints.py`.
- Added SQLite-backed fast tests for normalization and constraints.
- Added a Postgres integration test that runs when `POSTGRES_TEST_DATABASE_URL` is configured.
