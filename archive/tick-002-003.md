# AM-002-003: Define Normalized Phase 2 Tables

Status: `done`
Date: 2026-05-13

## Objective

Add normalized Phase 2 database table definitions and an additive migration without implementing gate execution, dedupe enforcement, email adapters, Gmail sending, OpenAI API usage, or frontend work.

## Decision

Completed-contact history is represented by `outreach_records`. Future active send reservations are represented by `send_reservations`. Candidate `companies` and `contacts` remain importable research records and do not themselves decide whether outreach is allowed.

## Changes

- Added SQLModel tables for profile, master CV, and policy snapshots.
- Added company, contact, fit evaluation, email draft, and send intent tables.
- Added future-compatible imported gate result, send reservation, and outreach record tables as data structures only.
- Added Alembic migration `0176dbbb5e28_create_phase_2_domain_tables.py`.
- Updated migration and boundary tests for the Phase 2 table set.
- Added a Phase 2 domain model persistence smoke test.

## Verification

- `uv run --python 3.12 --extra test pytest -q`
- `DATABASE_URL=sqlite:///./backend/alembic-domain-check.db uv run --python 3.12 alembic upgrade head`
- `DATABASE_URL=sqlite:///./backend/alembic-domain-check.db uv run --python 3.12 alembic check`
- Boundary search found no Gmail, OpenAI, SMTP, or email adapter implementation outside tests that assert their absence.

## Audit

No code path was added for sending email, calling Gmail, invoking an LLM, evaluating gates, or reserving sends. The migration is additive and its downgrade is intentionally disabled to avoid destructive rollback behavior.
