## Safety Boundary

The reservation service runs deterministic gate checks and creates a `SendReservation` only when the checks pass. It does not commit by itself, call an adapter, create outreach records, send email, or expose a public route.

The private fake adapter handoff still requires a `reserved_for_send` gate result and a matching active/reserved reservation. Public OpenAPI checks continue to reject send, reservation, handoff, and email-delivery paths.

No Gmail, SMTP, external provider, public send endpoint, OpenAI dependency, or real send path was added.

## Review Fixes

A gpt-5.5-medium reviewer found two issues before closure:

- The adapter guard could be spoofed by an injected adapter using provider string `fake_dry_run`. The handoff now requires the concrete `FakeDryRunEmailAdapter` type.
- Existing reservation reuse did not verify company and dedupe fields. Reuse now verifies them, with regression tests.
