# Tick AM-006-004: Run Import Integration

Date: 2026-05-15

## Result

Connected generated run folders, Codex exec metadata, and schema-backed import into one backend-visible integration path.

## Changes

- Added `backend/app/agents/codex_run.py`.
- Added `CodexRunService.prepare_execute_import(...)`.
- The service:
  - prepares a scoped run folder with `RunFolderGenerator`,
  - executes Codex through `CodexExecAdapter`,
  - imports only files under `output/` when execution succeeds,
  - skips import when execution fails,
  - writes a `codex_run_import_skipped` audit record on failed execution.
- Added integration tests with fake Codex runners:
  - successful runner writes a valid `user_profile.json`, which imports as a candidate snapshot;
  - failing runner writes stdout-like content, which is not imported or trusted.
- Existing dashboard-readable endpoints expose the resulting state:
  - `/runs/{run_id}`
  - `/runs/{run_id}/validation-results`
  - `/audit-logs?run_id=...`

## Related Fix

Fixed the live tmux chat bridge by changing `pane_command()` to avoid tmux `#{...}` format strings through `wsl.exe`, which were being mangled and causing `/onboarding/chat/{run_id}/start` to return 502 even when the pane existed.
